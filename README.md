# Личные финансы на Java

[![Java CI](https://github.com/Timur3005/personal-finance-java/actions/workflows/ci.yml/badge.svg)](https://github.com/Timur3005/personal-finance-java/actions/workflows/ci.yml)

Консольное backend-приложение для управления личными финансами: несколько пользователей, кошельки, доходы, расходы, категории, бюджеты, отчёты и переводы. Рабочие данные находятся в памяти, между сеансами сохраняются в файле. База данных и сервер не нужны.

## Быстрый старт

Нужен **JDK 17 или новее**. Maven устанавливать отдельно не требуется: Maven Wrapper загружает закреплённую версию 3.9.9 с проверкой SHA-256. При первой сборке нужен интернет. Для macOS/Linux нужны `sh` и `curl` либо `wget`.

```sh
git clone https://github.com/Timur3005/personal-finance-java.git
cd personal-finance-java
./mvnw clean verify
java -jar target/finance.jar
```

Windows:

```powershell
.\mvnw.cmd clean verify
java -jar target/finance.jar
```

Другой каталог данных:

```sh
java -jar target/finance.jar --data-dir /tmp/my-finance
```

Внешних библиотек во время запуска нет. JUnit 5 и инструменты сборки Maven скачивает автоматически; версии указаны в `pom.xml`.

## Пример сеанса

```text
register alice
<на следующей строке введите пароль>
login alice
<на следующей строке введите пароль>
category add income "Зарплата"
category add expense "Еда"
income "Зарплата" 60000
budget set "Еда" 4000
expense "Еда" 800
report
logout
exit
```

Пароль вводится отдельной строкой, без угловых скобок; в интерактивном терминале ввод скрыт. При перенаправлении stdin Java Console недоступна: ввод читается построчно. Не записывайте настоящие пароли в сценарии и историю команд.

## Команды

Ключевые слова команд — на английском, сообщения — на русском. Аргументы с пробелами заключайте в двойные кавычки. В таблице `<...>` обозначает обязательный аргумент, `[...]` — необязательный; сами скобки вводить не нужно.

| Команда | Назначение |
| --- | --- |
| `help` | Справка и примеры |
| `register <login>` | Регистрация; далее запрашивается пароль |
| `login <login>` | Вход; далее запрашивается пароль и восстанавливается состояние |
| `logout` | Сохранить состояние и выйти из аккаунта |
| `exit` | Сохранить данные и завершить приложение |
| `category add <income\|expense> <name>` | Создать доходную или расходную категорию |
| `category list` | Список категорий |
| `category rename <income\|expense> <old> <new>` | Переименовать категорию вместе с историей и бюджетом |
| `category delete <income\|expense> <name>` | Удалить неиспользуемую категорию |
| `budget set <category> <amount>` | Установить или изменить бюджет расходной категории |
| `budget remove <category>` | Убрать бюджет, сохранив категорию и операции |
| `income <category> <amount> [yyyy-MM-dd] [description]` | Добавить доход |
| `expense <category> <amount> [yyyy-MM-dd] [description]` | Добавить расход |
| `transfer <login> <amount> [description]` | Перевести деньги другому зарегистрированному пользователю |
| `report [options]` | Сводка доходов, расходов, баланса, категорий и бюджетов |
| `history` | История операций |
| `export <path.csv>` | Экспортировать снимок своего кошелька |
| `import <path.csv>` | Проверить снимок и заменить свой кошелёк |

Дату можно опустить: используется текущая. Если описание начинается с текста, похожего на дату, задайте дату операции явно. Дата должна существовать и иметь формат `yyyy-MM-dd`. Суммы — положительные, с точкой и не более чем двумя знаками после разделителя. Нулевой бюджет разрешён. Валюта одна — рубли. Логины чувствительны к регистру.

Категории создаются до добавления операций; неизвестные категории и неверные аргументы дают ошибку, после которой можно продолжить ввод. Доходная и расходная категории с одинаковым именем — разные категории. Удалить категорию с операциями нельзя.

### Отчёты и фильтры

```text
report
report --type expense --categories "Еда" "Такси"
report --from 2026-11-01 --to 2026-11-30
report --type income --categories "Зарплата" --file exports/salary.txt
history
```

`--from` и `--to` включают граничные дни. После `--categories` перечисляйте имена до следующего параметра `--...`. Можно сочетать фильтры. Все выбранные категории проверяются: опечатка не будет молча пропущена. Отсутствие подходящих операций обозначается в отчёте.

Параметры отчёта также поддерживают `--option=value`. Для имён категорий, начинающихся с `--`, используйте `report --categories=--Food --categories=--Taxi`: `--categories` можно повторять. Для значений с пробелами заключите весь аргумент в кавычки, например `"--categories=Коммунальные услуги"`.

**Бюджеты действуют за всю историю кошелька.** Фильтр дат ограничивает статистику операций, но не меняет общую базу расчёта бюджета. Для категории показываются установленный лимит, расходы и остаток; категории без лимита тоже входят в статистику.

Предупреждения выводятся при использовании не менее 80% бюджета, исчерпании и превышении лимита, превышении расходов над доходами и нулевом балансе. Обычный расход допускает отрицательный баланс; перевод требует достаточного остатка.

### Переводы

```text
register bob
<пароль>
login alice
<пароль>
transfer bob 1000 "Возврат долга"
history
logout
login bob
<пароль>
history
```

Перед примером завершите активный сеанс командой `logout`. Перевод создаёт расход отправителя и доход получателя с идентификатором перевода и контрагентом. Перевод себе, несуществующему пользователю, неверная сумма или недостаточный баланс отклоняются без изменения кошельков.

### Экспорт и импорт

```text
export exports/alice.csv
import exports/alice.csv
report --file exports/report.txt
```

CSV в UTF-8 содержит категории, бюджеты и операции только текущего кошелька; учётные данные не экспортируются. Имена с запятыми, кавычками и переводами строк экранируются. Формат является снимком состояния: импорт **заменяет** кошелёк, повторный импорт не добавляет дубликатов. Сначала экспортируйте резервную копию. Некорректный файл отклоняется целиком.

Импорт старого снимка откатывает только личный кошелёк. Он не отменяет переводы и не изменяет кошелёк контрагента. Это учебный инструмент резервного копирования, а не банковская система сверки переводов.

## Хранение и ограничения

- По умолчанию используется каталог `data/` относительно текущей рабочей папки. Запускайте приложение из одной папки или задавайте постоянный `--data-dir`.
- Состояние сохраняется при регистрации, выходе из аккаунта и завершении (`exit` или конец stdin). Переводы сохраняются вместе, одним снимком. Не закрывайте процесс принудительно: изменения после последнего сохранения могут потеряться.
- При авторизации данные восстанавливаются из снимка. Во время работы все расчёты выполняются в памяти.
- Файловое хранилище заменяется через временный файл; повреждённые данные не заменяются пустым состоянием. Ошибки чтения и записи показываются пользователю.
- Один каталог данных можно открыть только одним процессом приложения.
- Пароли хешируются PBKDF2 с индивидуальной случайной солью. Сами финансовые данные не зашифрованы: храните каталог данных в безопасном месте.
- Каталоги `data/`, `exports/`, `target/` исключены из Git. Не коммитьте свои финансовые данные и резервные копии из других папок.

## Проверка

```sh
./mvnw test          # unit- и интеграционные тесты
./mvnw clean verify  # тесты, runnable JAR и Checkstyle
```

Тесты используют временные каталоги и не трогают личный `data/`. Отчёты JUnit находятся в `target/surefire-reports/`, JAR — `target/finance.jar`.

Проверяются авторизация и изоляция пользователей, расчёты и точность денежных сумм, бюджеты и оповещения, фильтры, переводы, сохранение и перезапуск, повреждение файлов, CSV и CLI. [Пример из задания](examples/assignment.commands) можно выполнить в отдельном каталоге данных:

```sh
java -jar target/finance.jar --data-dir /tmp/finance-assignment < examples/assignment.commands
```

Используйте новый каталог для каждого повторения сценария. Ожидаемые суммы: доход **63000.00**, расходы **8300.00**, баланс **54700.00**. Остатки: Еда **3200.00**, Развлечения **0.00**, Коммунальные услуги **-500.00**.

## CI

[GitHub Actions](https://github.com/Timur3005/personal-finance-java/actions) запускается на `push`, `pull_request` и вручную. Ubuntu + Temurin 17, команда `./mvnw --batch-mode --no-transfer-progress clean verify`. При ошибке тестов или Checkstyle job завершается неуспешно. Workflow сохраняет отчёты JUnit и, при успешной сборке, JAR в артефактах запуска.

## Архитектура и модули

| Каталог | Ответственность |
| --- | --- |
| `src/main/java/ru/mephi/finance/core` | Модели, денежные расчёты, валидация, бизнес-правила, интерфейсы хранения |
| `src/main/java/ru/mephi/finance/infra` | Файловое хранилище, блокировка, CSV и хеширование паролей |
| `src/main/java/ru/mephi/finance/cli` | Разбор команд, форматирование отчётов и запуск |
| `src/test/java` | Unit- и интеграционные тесты |
| `config/checkstyle.xml` | Правила оформления Java |
| `.github/workflows/ci.yml` | Автоматическая сборка и проверка |
